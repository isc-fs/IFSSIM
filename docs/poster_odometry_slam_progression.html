The 9-state EKF

State vector — 9 dimensions, body-frame mechanics with Coriolis cross-terms in the predict step.

x = [ X, Y, THETA,      // pose in world frame
      VX, VY, OMEGA,    // body-frame velocities
      BA_X, BA_Y,         // accel bias
      BG_Z ]               // gyro bias

predict:  v̇x = ax + ω·vy      // ← Coriolis
          v̇y = ay − ω·vx      // ← Coriolis
          ω  = gyro_z − BG_Z   // assignment, not integration

correct:  RPM      → observes VX
          steering → observes OMEGA (kinematic bicycle)
          NHC      → observes VY ≈ 0 (lateral-slip-bounded)

Calibration: 3 s of stationary IMU samples at activate → estimates accel + gyro biases and gravity vector. Without it, post-activation drift is fatal.

The bug — a quiet Kalman cross-correlation leak

1. The propagation builds a correlation

The predict step's Jacobian has
F[OMEGA, BG_Z] = −1  (ω = gyro − BG_Z)
F[VX, BG_Z] = −vy·dt
F[VY, BG_Z] = +vx·dt

So P[BG_Z, OMEGA] and P[BG_Z, VX/VY] become non-zero after a single tick of propagation.

2. The correction multiplies it back

Any correction with H picking up ω (steering), vx (RPM), or vy (NHC) computes

K = P · Hᵀ / S

and applies x += K · y. Because P[BG_Z, observed] ≠ 0, the Kalman gain K[BG_Z] ≠ 0 too — every non-gyro observation pulls the gyro-bias state.

3. Bias walks; θ integrates wrong

Kinematic-bicycle residuals carry model error (tire slip, suspension flex) — not gyro bias information. But the EKF can't tell the difference. During a 15 s corner, BG_Z walked ±1.8 °/s.

Integrated over the corner: ~27° of phantom yaw in /odom.angular.z, then position drift via vx · sin(θ_err).

What we left alone

The factor graph SLAM structure didn't change. Cone DA stayed Euclidean-gated. Calibration stayed at 3 s. RPM_TO_MS stayed at 0.00821 (re-derivation showed it's already correct to 0.05 %).

The fix was entirely in how the EKF distributes a single observation's residual across its 9 states.

What we tried and rolled back

  • sigma_bg_walk 1e-4 → 1e-5: bias walk grew, not shrunk — process noise was never the issue.
  • Disable correct_steering entirely: lost cone-DA cascade later but introduced a vy issue.
  • Standard P = (I−KH)P with K[BG_Z]=0: drove P non-PSD, NaN'd covariance, collapsed /Path. Joseph form fixes this.

What's still left

With /odom and SLAM both clean, the lap still ends at the same physical corner. Cause is now controller saturation — Stanley commands full lock at ~1 m of cross-track error, oscillates, and the car physically spins.

That's a separate problem with separate fixes (cross-track gain, yaw-rate damping). The signal layer below it is now solid.
